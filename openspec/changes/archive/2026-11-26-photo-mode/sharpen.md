# Sharpen

## Request

> 4問目の問題だけど、新婦を当てるゲームだから写真の下に説明は出したくないんよね。
> 4問目だけ事前にa,b,c表示したいんよね。別の問題モードにしたほうがいいんかね
> いや、写真当てるモードにしたいな。

対話で確定した前提: 写真当てモードは「発表前からラベルを出す」と「選択肢の説明を持たない」をまとめたもの。書き方は写真当ての問題だけ `mode: photo` と書き、省いた問題は今まで通り。

## Sharpened

写真当てモード `mode: photo` を足す。

- **問題データ**: 問題は `mode: photo` を書ける。省くと今まで通りの「一番高いものを当てる」問題。写真当ての問題の選択肢は `note` を書けず、書くと検証に失敗する。写真当てでない問題の `note` は今まで通り必須。正解は rank 1。
- **画面**: 写真当ての問題は、発表前から両画面の各写真の左上にラベルを出し、写真の下に説明を出さない。発表後は今まで通り。
- **参加者に届くデータ**: 写真当ての問題だけ、表示順のラベル列を含める。ほかの問題のラベルは今まで通り正解発表まで届けない。
- **範囲外**: 正解発表の表示、めくりと紙吹雪の演出。

## Current System

- 問題は出題形式を持たない。正解は rank 1（`src/question-set/model.ts` の `answerOf`）。
- `note` は必須（`src/question-set/parse.ts:55`）。
- 公開形の選択肢は `image` と `note`。ラベルは公開形にない（`src/question-set/model.ts:44`・`:57`）。
- `OptionCard` は発表後だけ写真の中央に `.label-bar` を重ねる（`src/ui/OptionCard.tsx:21`）。
- ビルドの漏洩検査は、公開データの選択肢がラベルを持たないことと、キーが許可リストと完全一致することを確かめる（`tests/build/leak.test.ts`）。

## Done Means

- 単体テストで、写真当ての問題が説明なしで検証を通り、説明を書くと失敗し、未知の mode が失敗することと、公開形が写真当ての問題だけ表示順のラベル列を持つことを確かめる。
- ビルドの漏洩検査で、写真当てでない問題のラベル列が null であることを確かめる。
- E2E で、写真当ての問題は発表前から両画面にラベルが出て説明が出ず、ほかの問題は発表前にラベルが出ないことを確かめる。
- `pnpm typecheck`・`pnpm test`・`pnpm e2e`・`pnpm build`・`openspec validate photo-mode` が通る。
