# Sharpen

## Request

> 問題終わった後のなんかいるかな？
> 都度リアルで回答してもらって運営で集計かな
> 結果発表だけの画面でアニメーションとかつけて出して、その次の画面で景品数とかの画面をもう一回出すのは？

対話で確定した前提: 各テーブルの回答は問題ごとに運営が会場で集めて集計する。アプリは正解数を数えない。そのため、全問の正解一覧（答え合わせの画面）は作らない。sharpen の後に依頼者から「こっちに確認必要なことがでてくるまで自分で進めて」と任されたので、下の「依頼者に任された決定」は既定のとおりに決めた。

## Sharpened

最終問の後に、結果発表の画面と、ランクと景品の画面を足す。

- **並び**: 最終問の次は結果発表、その次はランクと景品。`prizes` を書いていない問題セットでは、ランクと景品の画面を出さずに結果発表で終わる。◀ で同じ順に戻る。
- **結果発表の画面**: 両画面に「結果発表」を大きく出し、文字を 1 字ずつ落とすアニメーションと紙吹雪を付ける。reduced motion では動かさない。
- **ランクと景品の画面**: 第 1 問の前と同じ表を、見出しを変えて出す。参加者画面はこの表だけを出す。
- **参加者に届くデータ**: この 2 画面は画面の種類だけを持ち、正解情報を持たない。
- **範囲外**: 正解数の集計と、テーブルごとの成績の表示。

依頼者に任された決定:

1. 紙吹雪は、司会が操作して結果発表の画面にしたときだけ打つ。結果発表の画面の途中で開いた画面や再接続した画面では打たない（正解発表と同じ扱い）。
2. 最後の 2 画面の見出しは、小見出しを `RESULT` にし、ランクと景品の画面の見出しは「ランクと景品」のまま。
3. 最後の 2 画面では Space・Enter は何もしない。並びの最後の画面では ▶ を押せない。
4. `prizes` がないときは結果発表の画面だけを出す。

## Current System

`how` は 1 つの subsystem（会場の進行と両画面）の中に収まる問いなので、explainer を分けず、本文で読んだ。

- 画面の並びは `deckOf` が問題セットから作り、`sequence` が `title → intro → 第 1 問 … 最終問` の配列にする（`src/deck/cursor.ts:15`・`:31`）。`move` は並びの両端で止まるので、最終問では ▶ が無効になる（`src/deck/cursor.ts:41`、ボタンは `src/host/HostScreen.tsx:168`）。
- 会場の状態機械は位置を `VenueState` にし、問題でない画面の正解発表（Space・Enter）を無視する（`src/venue/machine.ts:32`）。保存形（`src/venue/room.ts:17`）と配信形（`src/venue/protocol.ts`）は phase ごとの許可リストで、未知の phase は読めない。
- 配る状態は `viewOf` だけが作る。問題でない画面は `{ phase }` だけを返す（`src/venue/view.ts:23`）。
- 紙吹雪の合図は `celebrationOf` が「司会の操作で届いた正解発表」のときだけ出す（`src/venue/socket.ts:63`）。つないだ直後のフレーム（`joined`）では出さない。
- 司会画面はルール画面・ランクと景品の画面を `IntroScreen` で描く（`src/host/HostScreen.tsx:37`、見出しは `src/ui/IntroScreen.tsx:4`）。参加者画面は届いた画面を手元の問題セットで出せないときタイトル画面にする（`src/guest/GuestScreen.tsx:17`）。

## Done Means

- 単体テストで、並びが `最終問 → 結果発表 → ランクと景品` になり、`prizes` がなければ結果発表で終わること、最後の 2 画面で正解発表が無視されること、2 画面の配信形が `{ phase }` だけで正解情報を持たないこと、紙吹雪の合図が操作で届いた結果発表でだけ出ることを確かめる。
- E2E で、司会画面が最終問から結果発表へ進み紙吹雪を出し、▶ と Space が効かず ◀ で最終問へ戻ること、参加者画面が結果発表と紙吹雪を出し、途中から開いたときは紙吹雪を出さないことを確かめる。
- 実データの content E2E で、1920×1080 の結果発表とランクと景品の画面が枠からはみ出さないことを確かめる。
- `pnpm typecheck`・`pnpm test`・`pnpm e2e`・`openspec validate finale --strict` が通る。
